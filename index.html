03code

Write the code that holds under pressure.

In the Go training and scheduling service I own, two people booking the same instructor or vehicle at the same moment can't both succeed. The database decides, inside a locked transaction.

  • Angular 19 + NgRx on the front end, Go, Laravel and NestJS behind it
  • Row-level locks around every check-then-write sequence
  • Money stored as integer cents and posted through one journal path
scheduling/booking.gogo
// Two requests for the same slot: one wins, one gets ErrSlotTaken.
func (s *Scheduler) Book(ctx context.Context, r BookingReq) error {
  return s.db.WithContext(ctx).Transaction(func(tx *gorm.DB) error {
    var slot Slot
    // SELECT ... FOR UPDATE: concurrent bookers wait here
    err := tx.Clauses(clause.Locking{Strength: "UPDATE"}).
      Where("instructor_id = ? AND starts_at = ?",
        r.InstructorID, r.StartsAt).
      First(&slot).Error
    if err != nil {
      return err
    }
    if slot.Taken {
      return ErrSlotTaken
    }
    slot.Taken = true
    if err := tx.Save(&slot).Error; err != nil {
      return err
    }
    // other services sync from the event, not from shared tables
    return s.events.Publish(ctx, "slot.booked", slot)
  })
}

Products I've designed, built and shipped.

UrbanBoma live

Property management SaaS. Tenants, rent, accounts, payroll and maintenance stock in one place, for landlords and agencies across Kenya.

15 modules92 models112 migrations187 permissions
  • Single-database multi-tenancy: tenant-ID row scoping enforced by a global query scope, plus a platform → reseller → tenant hierarchy for white-label partners.
  • Double-entry accounting core: one journal path validates debits against credits, uses integer cents, and traces every line back to its source.
  • M-Pesa pipeline (STK, C2B, B2C): four independent safeguards, so a forged or repeated callback can't mark rent paid twice.
  • Kenya statutory payroll: PAYE, NSSF, SHA and Housing Levy, with rates held as configuration so past payrolls reproduce exactly.

Tykopass live

Event ticketing and organiser finance. The public pays with M-Pesa and gets a QR ticket instantly. Organisers get wallets, payouts, invoices, sales agents and commissions.

85 models161 migrations87 feature tests
  • Pooled-funds ledger: organiser wallets record claims against the platform pool, and every movement writes balance-before and balance-after inside a transaction.
  • Concurrency-safe issuance: row-level locks so the callback, its retry and an organiser's click can't all issue the same ticket.
  • Idempotent callbacks and one fee service, so the price shown is the price charged on every path.
  • Drift treated as expected: hourly reconciliation, daily balance snapshots and a rebuild-from-source path.
